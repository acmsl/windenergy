Control Terminal

What is the Control Terminal?

Remember: a wind turbine is designed to be a fully autonomous electrical power plant. It runs itself, makes its own decisions, and handles problems without human intervention - most of the time.

But sometimes humans need to interact with it:

  • Maintenance and repairs
  • Troubleshooting problems
  • Adjusting parameters
  • Commissioning and setup
  • Training and diagnostics

That's where the Control Terminal comes in. Think of it as the wind turbine's "dashboard" - the interface between humans and the machine.

What Makes Wind Turbines Special?

Before we dive into the Control Terminal, let's appreciate what the Controller has to deal with:

External challenges:

  • Hurricane-force winds
  • Lightning strikes (turbines are tall targets!)
  • Extreme temperatures (from -40°C to +50°C)
  • Ice accumulation on blades
  • Grid faults and power outages

Internal challenges:

  • Hydraulic leaks
  • Sensor failures or miscalibration
  • Bearing wear
  • Excessive vibrations
  • Component overheating
  • Control system glitches

The Controller's job:

Detect all these issues in real-time and respond appropriately:

  • Continue operating if safe
  • Adjust operations if conditions are marginal
  • Shut down safely if conditions are dangerous
  • Log everything for later analysis
  • Alert operators when human intervention is needed

The Control Terminal is how humans monitor this autonomous operation and intervene when necessary.

Types of Control Terminals

Integrated Panel-Mount Terminal

Some turbines have the Control Terminal built into the electrical cabinet:

Features:

  • Fixed installation at tower base
  • Touchscreen or buttons + display
  • Direct wired connection to Controller
  • Always available
  • Protected from weather

Advantages:

  • ✓ Always there when you arrive
  • ✓ No setup required
  • ✓ Can't be lost or forgotten
  • ✓ Direct, reliable connection

Disadvantages:

  • ✗ Can only use it at tower base
  • ✗ Limited screen size (space constraints)
  • ✗ Shared among all technicians

Portable Handheld Terminal

Many manufacturers provide portable terminals:

[Figure: Portable control terminal]

Features:

  • Rugged handheld device (like a tough laptop or tablet)
  • Connects to Controller via cable or wireless
  • Technician carries it
  • Can be used anywhere in tower/nacelle

Advantages:

  • ✓ Take it where you need it
  • ✓ Larger screen possible
  • ✓ Multiple technicians can have their own
  • ✓ Can store personal settings

Disadvantages:

  • ✗ Can be forgotten/lost
  • ✗ Battery needs charging
  • ✗ Can be damaged
  • ✗ Connection can be unreliable (especially wireless)

Modern Trend: Laptop/Tablet with Software

Increasingly, manufacturers provide:

  • Software application for Windows/Linux laptop
  • Or app for rugged tablet
  • Connects via Ethernet or WiFi
  • Same functionality as dedicated terminal

Why this is becoming standard:

  • Technicians already carry laptops
  • Software can be updated easily
  • Better graphics and interface possible
  • Can save logs and reports directly
  • Lower cost (no custom hardware)

What Can You Do with the Control Terminal?

1. Monitor Real-Time Status

The terminal shows current operating conditions:

Wind conditions:

  • Current wind speed (from anemometer)
  • Wind direction (actual compass direction)
  • Effective wind speed (accounting for nacelle misalignment)
  • Nacelle orientation

Mechanical status:

  • Blade rotational speed (RPM)
  • Generator rotational speed (RPM)
  • Blade pitch angle
  • DriveTrain acceleration
  • Current Cp (power coefficient - how efficiently extracting wind energy)

Electrical output:

  • Active power generated (kW)
  • Reactive power (kVAr)
  • Power factor (cos φ)
  • Voltage and current per phase
  • Total energy produced (kWh累積)

System health:

  • Temperatures (generator, gearbox, bearings, ambient)
  • Hydraulic brake pressure
  • Grid connection status
  • Which generator connection mode (4-pole or 6-pole)
  • Thyristor status
  • Bypass contactor status
  • Yaw motor status (CW/CCW)
  • Brake status

Safety status:

  • Overspeed detection status (HCU/VCU)
  • Tower vibration sensor
  • Grid phase status (all three phases present?)

2. View and Acknowledge Alarms/Incidents

This is one of the most important functions.

How the incident system works:

When something abnormal happens, the Controller creates an incident record:

Incident information includes:

  • Description: What happened ("Grid Phase 1 Lost")
  • Start time: Exactly when it began (YYYY-MM-DD HH:MM:SS.mmm)
  • Recovery time: When condition returned to normal (if it has)
  • Severity: How serious (information, warning, alarm, critical)
  • Action taken: What the Controller did (continued, reduced power, stopped)

Incident lifecycle:

Active incidents:

  • Shown in "Open Incidents" list
  • Highlighted in red or yellow depending on severity
  • Some require acknowledgment, others are automatic

Recovered incidents:

  • Condition has returned to normal
  • "Recovery time" field is filled in
  • May still require operator acknowledgment

Acknowledged incidents:

  • Operator has reviewed and understood
  • Clicks "OK" checkbox for the incident
  • Moves to "Incident History"

Example scenario - Grid fault:

Let's walk through what you'd see:

  1. Fault occurs (2025-10-11 14:23:47.234):
    • Grid Phase 1 voltage drops to zero
    • Controller detects this within 100ms
  2. Incident created (2025-10-11 14:23:47.334):
    • Description: "Grid Phase 1 Voltage Lost"
    • Start time: 14:23:47.234
    • Recovery time: [empty]
    • Appears in "Open Incidents" list
  3. Controller responds:
    • Waits 2 seconds (might be momentary fault)
    • Still missing? Initiates cutout sequence
    • Reduces power to zero
    • Opens bypass contactors
    • Another incident created: "Cutout Due to Grid Fault"
  4. Grid recovers (2025-10-11 14:24:15.123):
    • Phase 1 voltage returns to normal
    • Recovery time updated: 14:24:15.123
    • Incident still in "Open Incidents" (needs acknowledgment)
  5. Technician arrives, sees in Control Terminal:

   OPEN INCIDENTS:

   [ ] Grid Phase 1 Voltage Lost

       Start: 2025-10-11 14:23:47.234

       Recovered: 2025-10-11 14:24:15.123

       

   [ ] Cutout Due to Grid Fault

       Start: 2025-10-11 14:23:49.445

       Recovered: 2025-10-11 14:24:20.567

  1. Technician acknowledges:
    • Checks both checkboxes in "OK" column
    • Incidents move to "Incident History"
    • Turbine can now restart (if conditions allow)

Why this system is important:

  • Forces human review of significant events
  • Prevents automatic restart after serious faults
  • Creates audit trail
  • Helps identify recurring problems
  • Legal/insurance documentation

3. Send Commands

The Control Terminal is how operators tell the turbine what to do:

START Command

Tells the Controller to begin the cutin (startup) sequence.

What happens when you press START:

The Controller doesn't just blindly start up. It goes through a checklist:

Pre-start checks:

  1. Are all open incidents acknowledged?
  2. Is "Manual STOP" cleared (operator ready)?
  3. Is wind speed in acceptable range?
  4. Is grid voltage present and stable?
  5. Are all critical temperatures in normal range?
  6. Is hydraulic pressure adequate?
  7. Are brakes functioning?
  8. Any safety interlocks active?

If ANY check fails:

  • Display error message explaining why
  • Log the rejected start attempt
  • Wait for conditions to improve

If ALL checks pass:

  • Begin cutin sequence (we'll see this in detail later)
  • May include cable untwisting first if needed
  • Then nacelle orientation
  • Then the actual power-up sequence

STOP Command

Tells the Controller to shut down (cutout).

Types of STOP:

Normal STOP (what you do with the button):

  • Controlled, gradual shutdown
  • Reduces power smoothly
  • Disconnects at zero or low power
  • Blade pitch to feather position
  • Apply brakes gently
  • Takes 30-90 seconds typically

Emergency STOP (if something goes wrong):

  • Much faster
  • May use emergency brake (not ideal)
  • Prioritizes safety over gentleness
  • Can stress components but necessary

The "Manual STOP" incident:

When you press STOP:

  • Creates incident: "Manual STOP"
  • Remains in "Open Incidents"
  • Must be acknowledged (OK checkbox) before START will work
  • This prevents accidental or premature restart

Manual Yaw Control

When turbine is stopped, you can manually control nacelle orientation:

The yaw buttons:

In normal operation (turbine running):

  • "Yaw Left" and "Yaw Right" buttons are grayed out (inactive)
  • Automatic yaw control is in charge

When stopped:

  • Buttons become active (you can click them)
  • Press and hold "Yaw Left" → nacelle rotates counterclockwise
  • Press and hold "Yaw Right" → nacelle rotates clockwise
  • Release button → rotation stops

Safety limits still apply:

Even in manual mode:

  • Can't exceed max cable twist (±2.5 turns)
  • If approaching limit, that direction becomes disabled
  • Grid must be available (yaw motors need power!)

When you'd use manual yaw:

Initial positioning:

  • After maintenance, setting starting orientation
  • Positioning for blade work (park blades vertically)

Troubleshooting:

  • Testing yaw motors
  • Checking for mechanical binding
  • Verifying position sensors

Not for normal operation:

  • Automatic yaw control is always better
  • Manual should only be used when necessary

4. View Operating Parameters

The Control Terminal displays key operating parameters:

DriveTrain parameters:

  • Moment of Inertia: How much rotational "mass" the system has
    • Affects acceleration/deceleration rates
    • Displayed in kg·m²
    • Typically 3,500,000 kg·m² for this simulator
  • Air Density: Current atmospheric density
    • Affects power extraction (denser air = more power)
    • Varies with temperature, pressure, humidity, altitude
    • Typically displayed in kg/m³
    • Standard: 1.225 kg/m³ at sea level, 15°C

Cp (Power Coefficient):

  • How efficiently the blades are extracting power from wind
  • Theoretical maximum: 0.59 (Betz limit)
  • Practical maximum: 0.45-0.50 for modern blades
  • Real-time value shown
  • Varies with wind speed, RPM, and pitch angle

Generator Connection Mode:

  • "Large Generator" (4-pole, 1500 RPM synchronous speed)
  • "Small Generator" (6-pole, 1000 RPM synchronous speed)

Control System Status:

  • Which state machines are in which states
  • Recent events
  • Active control algorithms

5. Access Detailed Information

Beyond the main screen, the Control Terminal provides access to:

System Logs:

  • Complete history of all events
  • Can filter by date, type, severity
  • Export to file for analysis

Sensor Raw Data:

  • Every sensor value
  • Update rates
  • Health status of sensors
  • Calibration information

Internal Signals:

  • Controller calculations
  • Intermediate values
  • Algorithm states
  • Not normally visible in actual turbines!

Performance Statistics:

  • Energy production summaries
  • Availability percentage
  • Downtime analysis
  • Fault frequency statistics

6. Change Operating Parameters

Access Levels:

Not everyone can change everything! The Control Terminal has multiple access levels:

Level 1 - Operator (basic):

  • Can view status
  • Can START/STOP
  • Can acknowledge incidents
  • Can use manual yaw
  • Cannot change parameters

Level 2 - Technician:

  • Everything in Level 1, plus:
  • Can change some operational parameters
  • Can run diagnostic tests
  • Can access detailed logs
  • Cannot change safety-critical parameters

Level 3 - Engineer:

  • Everything in Level 2, plus:
  • Can change safety parameters
  • Can modify control algorithms
  • Can update firmware
  • Can disable safety interlocks (temporarily, for testing)

Level 4 - Manufacturer:

  • Full access to everything
  • Can change factory settings
  • Can recalibrate sensors
  • Usually password-protected
  • Often requires manufacturer's remote authorization

Example - changing a parameter:

Let's say a technician wants to change the maximum cable twist before automatic untwisting:

  1. Log in with technician credentials
  2. Navigate to Parameters menu
  3. Find "ControllerYawing.MaxCableTwist"
  4. Current value: 2.5 turns
  5. Click to edit
  6. Enter new value: 2.0 turns
  7. Confirm (are you sure?)
  8. Log the change (who, when, old value, new value)
  9. Apply - takes effect immediately

Safety mechanisms:

  • Can only change within allowed range (min/max)
  • Some changes require turbine to be stopped
  • Critical changes may require manufacturer authorization code
  • All changes are logged (audit trail)
  • Usually can revert to factory defaults

For those learning how the Controller works, this is invaluable! You can see exactly:

  • What event caused it to get there
  • What transitions are possible from current state

In Practice - A Day with the Control Terminal

Morning arrival at the wind farm:

  1. Check on each turbine:
    • Drive to tower base
    • Connect Control Terminal (or view panel terminal)
    • Quick status check:
      • Any open incidents? → Investigate
      • Production OK? → Note power output
      • Any unusual temperatures? → Monitor
    • Takes 2-3 minutes per turbine
  2. Found a problem - one turbine stopped:
    • Open Incidents shows: "Generator Temperature > 140°C"
    • Recovered: Yes (temperature now 95°C)
    • What happened?
    • Check Incident History
    • See related event 2 hours ago: "Cooling Fan Failed"
    • Ah! Fan failed, generator got hot, shutdown occurred
    • Fan has since restarted (automatically retried)
    • Temperature came down
  3. Decision time:
    • Acknowledge the incidents
    • Press START
    • Monitor for 30 minutes to ensure stable
    • If temperature stays normal → OK
    • If rises again → Fan needs replacement, take turbine offline

During scheduled maintenance:

  1. Taking turbine offline for blade inspection:
    • Press STOP on Control Terminal
    • Wait for complete shutdown
    • Verify: Blade Pitch = 90° (feathered)
    • Verify: Brake = Applied
    • Verify: Generator Speed = 0 RPM
  2. Position blades for inspection:
    • Use Manual Yaw to orient nacelle
    • Need blade #1 pointing straight up
    • Watch 3D view or reference marks
    • Lock yaw brake when positioned
  3. Perform inspection (blade team does their work)
  4. Restart after maintenance:
    • Clear "Manual STOP" incident
    • Press START
    • Monitor startup sequence
    • Verify normal operation
    • Document maintenance in log

Why the Control Terminal Matters

The Control Terminal is your window into the turbine's "mind":

For Operations:

  • Know what every turbine is doing
  • Catch problems early
  • Make informed decisions about production

For Maintenance:

  • Diagnose faults quickly
  • Monitor repairs in real-time
  • Verify fixes worked

For Optimization:

  • Analyze performance data
  • Adjust parameters for site conditions
  • Maximize energy production

For Safety:

  • Ensure all safety systems working
  • Review incident patterns
  • Prevent dangerous situations

For Learning:

  • See exactly how the turbine operates
  • Understand control algorithms
  • Train new technicians

In the simulator, the Control Terminal is even more powerful because you can:

  • See internal signals not available in real turbines
  • Force failure conditions safely
  • Experiment with parameters
  • Learn without consequences!
